# SECURITY · 结构性安全 vs 机制防御(成文版)

> 分工先说清:**结构性安全**=对手预算无限也改不动的性质(由状态设计给出);**机制防御**=只抬高攻击成本、不抬上限高的闸门(限频/冷却/体积帽)。本文把两类各自钉在代码出处上,已知面直说不装。

## 1. 结构性安全:不依赖任何"防"的设计

### 1.1 claim 只追加、无余额读取语义 → 链重组不改结果
`claim(id,color)` 只做三件写:`c.owner=msg.sender`(last-write-wins)、`c.color`、`c.heat+1`,外加 `emit Claim(id,who,color,heat)`——**不读余额、不转账、不 external call、无全局状态**(`contracts/Battlefield.sol:25-38`;头注释明训"不要加 totalClaims++",Battlefield.sol:5)。推论,对任意区块重组序列:
- 格子终态 = 按最终链重放全部 `Claim` 事件的结果,而每个事件只写自己那一个 slot(indexed `id`,Battlefield.sol:21)→ **重放与增量重建必然收敛到同一版图**;
- 不存在"半途状态"可供利用:没有共享中间量,重组只可能换某格的 last writer,不可能改别格、更不可能凭空造出未被任何交易写过的归属;
- 到场证明的可查性同理:一笔已落块 claim 的哈希/区块号在任何重组后仍指向同一次写入,这是"区块浏览器可查"这句话的安全根基。

### 1.2 无全局计数器 → 无跨交易干扰
写集两两不相交(每格独占 slot,README.md:24-43)⇒ 并发 claim 之间没有可竞争对象:一笔成功与否、烧多少 gas、何时入块,与同时刻其他格上的交易**零耦合**。攻击者无法用"狂写某格"拖慢或饿死别的格(每道自己的 reserve 限速封顶,见 4.4);这正是并行 EVM 上"零重执行税"的安全学另一面。

### 1.3 零主网资产
所有钱包是 throwaway 测试网账号,`.env` 注释原文"只用于测试网,别用主钱包"(.env.example:5);README 收尾"If you fork this, use accounts you are willing to burn"(README.md:237-239)。链上事故的最大损失 = 一场 demo 的测试币预算(docs/COST.md),不是资产。

### 1.4 观众不碰任何秘密
观众端零签名:无钱包、无 gas、无种子短语(README.md:18,98)。`join.ts` 不发任何签名材料,只发 `{cell,faction,clientId,nick,sync}` 四个自报字段(web/src/join.ts:528-538)。被拖库也拖不出观众的东西——观众侧攻击面是空集。

## 3. 两类对比(一段话版本,答评委用)

> "你们的限频会不会被绕?"——会,机制层的东西都可以被更贵的对手绕。**但我们最重要的性质不靠限频活着**:格子归属由事件重放唯一决定(§1.1),格间互不干扰(§1.2),全场零主网资产(§1.3),观众手里没有可偷的东西(§1.4)。限频被绕穿的最坏结果是"这一场的测试币提前烧完、顶栏如实掉档"——损失被结构性设计封顶在预算维度,而预算就是 `budget.mjs` 上台第 0 步要算的那个数。机制负责体验,结构负责生死。

## 4. 已知面(直说不装)

1. **Sponsor 服务端是可信边界**。观众点击由中继 8 key 代签代付(README.md:106-108),链上 `who` = 中继地址而非观众本人:信任模型是"你信这台中继此刻没有篡改你点的位置"。署名 `nick` 与 `clientId` 全是自报字符串,服务端消毒≠验真。真人占比("real-person %")的证据强度到"带昵称格与匿名蜂群可区分"为止,再强就是幻觉。
2. **代付接口 CORS 全开**(index.mjs:1278-1283),任何网页都能拿它当免费 relayer。防线只有第 2 节两道桶;跨 IP 分布式脚本能持续消耗 sponsor 的 gas 预算——**这是花你自己的钱**的拒绝服务,处置 = 现场关闸(`MAX_PENDING` 调小/重启),而非"防住"。
3. **historyFrom/complete:false 的重建边界**:公共 RPC 只给 ~100 块日志窗(index.mjs:423-433),窗口外历史读不回——版图缓存因此"中继发过的一笔都不丢"(乐观写入 index.mjs:609-629),但纯旁观者重启中继只能看到近窗。`/api/state` 如实报 `complete:false`,界面不装知道(README.md:204)。
4. **heat 显示截断**:缓存侧 `heat & 0xff`(index.mjs:685-686,注释口径"与合约 uint32 截断后一致")与合约 `unchecked` 自增(Battlefield.sol:32-34)——uint32 溢出按 2^32 次/格计,演示规模结构不可达,不作风险论。
5. **合约输入面**:API 先验 `0≤cell≤2499 / 1≤faction≤4` 再发(index.mjs:1580-1587),`BadId()` 只是兜底——revert 也按 gasLimit 扣钱(README.md:55),所以"先验后发"是省 sponsor 钱的机制,不是安全边界;安全边界在 §1.1:写坏了也只坏那一格。
6. **未验证项沿用 README 口径**:真机触摸人体工学、投影光照下的可读性未实测(README.md:200-203)——安全文档不替视觉文档背书。

**不是什么的声明**:这不是资产托管系统,没有多签、没有热冷分离、没有审计;它的安全声明只覆盖"参与证明不可抵赖 + 单场损失封顶在测试币预算"这两个命题,越界使用(主网、真钱)请把 §1.3 的每个前提重新论证一遍。
