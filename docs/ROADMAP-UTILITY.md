# ROADMAP-UTILITY · 从"活动装置"到"参与证明中间件"的实用化路线
> 状态声明:今天是 v0.5 已跑通;v1-v3 是**规划**,deck 与口播只说"路线",不说"已有"。诚实边界不破。

## 0. 认输页的升华改写(一句话版)
旧句:"没有人需要一面永久的格子墙。"(真,但泄气)
新句:"**没有人需要一面墙——但每场活动、每堂课、每个社区,都需要一份谁也改不了的参与名单。**墙只是这个引擎今天的形状。"

## 1. 为什么这个痛点是真的(不是编的)
- **代签与灌水无处不在**:大学课堂点名到课率造假(综测按它计分——我们在场内,亲身受害);会议签到二维码秒完事、无法证明"人到了还在听";品牌活动参与数据全是主办方后台黑箱,赞助商年年为注水买单。
- **现有方案的共同缺陷**:要么中心化可改(钉钉签到、小程序集章),要么门槛杀死复参与(装钱包/记助记词/等确认)。POAP 证明了链上参与凭证有市场,但发币门槛和交互摩擦使它只能低频用。
- **我们的解锁点**:sponsor 代付(观众无钱包)+ 同步回执(0.7-2s 有反馈)+ 单格成本实测 **0.0066 MON(美分以下)**。低频时上链不值得——**成本与门槛降到这个量级,高频率参与第一次变得值得上链**。这是"只有并行 EVM 扛得住"的真实版本:不是快得炫,而是快与便宜到**日常可行**。

## 2. 三个高频垂直(按可验证性排序)
| 场景 | 频率 | 痛点付费方 | 引擎映射 |
|---|---|---|---|
| **课堂/工作坊链上点名** | 每周 | 学校/培训机构(综测、出勤即成绩) | claim=签到,格子=当堂互动题,color=选项 → 出勤+答题双证明,verify 页学生自查、老师免造册 |
| **会议/展览参与凭证** | 每场 | 主办方(向赞助商交付真实数据) | 扫码=到场,每格=一次互动;散场导出 claim bundle,不可抵赖 |
| **社区例行活动(AMA/投票式氛围)** | 每两周 | Web3 社区运营 | 同块 N EOA 分布即"活人浓度"指标,反 bot 靠 IP 桶+人肉节律(已实现) |

## 3. 版本路线(工程上都是今天的直接增量)
**v1 · 会话模板化(赛后 2 周)**
- `npm run new-campaign -- --name "计设001班" --cells 50x50 --question "..."`:自动部署新合约+生成二维码物料+预设阵营为选项/队伍
- 参与证明导出:地址→{全部 claim、区块、时间}签名 bundle(verify.html 已有查询内核,加一键下载)
- 复用件全部已存在:合约 38 行不动,relay/蜂群/导演台是参数化外壳

**v2 · 教育垂直闭环(1-2 月)**
- 教师端:题目=格子语义(color=选项,heat=提交次数),下课后出勤率+互动率看板
- 反代签升级:现场地理围栏+随机格验证(点"我左手边第三格"式口令)——把"手机在、人在"变可证
- 接入综测口径:导出格式对齐学校表单(我们在场内,这是别人没有的需求理解)

**v3 · 参与证明中间件(生态位)**
- relay 协议抽成 npm 包(`proof-relay`:多 key nonce 队列+同步回执+冷却/止付,全在 server/index.mjs 长出来了,文档化即产品)
- `claim(id,color)+Claim 事件` 作为开放 schema,任何前端可接;对标"十一秒"的接入面,我们横向它纵向
- DevRel 场景:每场 workshop 的"第一笔交易"由墙承载(今天 workshop 让大家部署 Hello World,明天我们的墙让 200 人 3 分钟同块落链——**这就是 Monad 要的销售话术本身**)

## 5. 风险与不做什么
- ❌ 不做"通用投票系统"(安全模型完全不同,别碰计票严肃性)
- ❌ 不承诺"防女巫彻底"(IP 桶+口令格只提高成本;学术场景够用,金融场景不够,直说)
- ⚠️ 教育场景落地需真实学校试点——**我们自己就是目标用户**,这是最便宜的可信度
