## 0. 三端一服务（先记住这张图）

**一条命令起全套：**

```bash
node scripts/stage.mjs --check
```

它构建三端 → 起 cloudflared 公网隧道 → 用隧道地址起中继 → 等隧道打通 → 打印三个地址 → 跑二维码验收。
Ctrl-C 退出会带走中继和隧道。

```
大屏      https://<隧道>/                ← 投影，评委看这个
观众页    https://<隧道>/join.html       ← 78 人扫码，手机点
导演台    https://<隧道>/director.html   ← 你的手机/平板（和大屏同一个 origin）
中继      http://localhost:8791          ← 把观众点击变成链上 tx（隧道指向它）
蜂群      npm run swarm                  ← 已注资车道数的背景压力（40 道=配置目标；实测跑过 17 道）
```

### 0.1 为什么必须是公网隧道，不能是局域网 IP

**这是本项目最容易当场翻车的一处，两个坑叠在一起：**

| 坑 | 症状 | 已修 |
|---|---|---|
| 二维码编码 `location.origin` | 主讲人用 `localhost` 开大屏 → 二维码写 localhost → 78 台手机全扫不开 | 前端改为向中继 `/api/config` 取 `joinUrl`；仍是回环就不画码，改出告警卡 |
| 中继选网卡取「第一个非 internal IPv4」 | 这台机器上命中 Tailscale 的 `100.94.99.48`（CGNAT）→ 全场没有一台设备路由得到 | 物理网卡优先，虚拟网卡降级，排除 169.254 |

**但即使两个都修好，局域网方案在会场仍然不成立**：本手册第 3 节要求「笔记本连 4G 路由、手机用自己的流量」——
那时手机和笔记本**不在同一个网络**，二维码里写 `10.x` / `192.168.x` 私网地址，手机照样路由不到。
和写 localhost 一样是死码，只是死得更隐蔽。

所以会场默认走 **公网 HTTPS 隧道**：任意手机、任意网络都能开。
`--lan` 模式只在「所有人连同一个 wifi」时才用。

### 0.2 控场指令走两条路（跨设备也能用）

导演台有两种投递通道，**同时启用**：

| 通道 | 覆盖场景 | 延迟 |
|---|---|---|
| `BroadcastChannel` | 同一浏览器同源页面（大屏和导演台在同一台机器上开两个窗口） | 0 |
| `POST /api/director` → 大屏轮询 | **跨设备**（笔记本放大大屏、平板/手机开导演台） | ≤1s |

状态栏会告诉你是哪条走通了：`已发送 · 同屏+跨设备` / `· 仅同屏` / `· 跨设备`。
**只显示「已发送」不带通道后缀、或者大屏没反应 = 有问题，别当成正常。**

`scripts/director-check.py` 用两个独立浏览器上下文（互不共享 BroadcastChannel）复现这个场景，
是门禁的第 5 道。

### 0.3 三个地址仍然建议同一个 origin

跨设备投递靠的是「两页都能访问到同一个中继」。如果大屏开隧道、导演台开局域网，
导演台 POST 不到中继（或者 POST 到别的机器），跨设备通道就断了。
`stage.mjs` 打印的三个地址天然同源，照着开最省事。

**端口注意**：本机 8787 被别的服务占用，中继已改用 **8791**。
换机器时先 `netstat -ano | grep 8791` 确认只有**一个**进程在听 —— 两个残留实例抢端口时，
其中一个可能是旧版本，会返回 404 且毫无提示。

## 1. 赛前 3 天：把钱和地址准备好

### 1.1 需要多少测试币（实测数据，不是估算）

**单笔 claim 成本 = gasLimit × gasPrice = 60,000 × 110 gwei = 0.0066 MON**

实测结论（已在本机链上验证）：
- `gasLimit` **必须 ≥ 60,000**。实测：50,000 → 0/3 成功；60,000 → 3/3 成功。
  单笔测试里 45,000 偶尔能过，但批量跑成功率接近 0 —— **别信单次运气，信批量统计**
- revert 照样扣 gas，所以 gasLimit 给低了不是省钱，是纯烧钱
- Monad 按 `gasLimit` 计费（`gasUsed == gasLimit`），给多了就是白烧钱
- `gasPrice` 下限约 100 gwei（链上 baseFee），用 110 gwei 最稳
- **交易类型**：我们的车道统一使用 **legacy + 显式 gasPrice**（全日志稳定）。注：仓库日志里**没有**存档 type-2 被拒的原始错误串，所以只陈述我们的做法，不宣称「Monad 拒绝 EIP-1559」——被追问时这样答才立得住
- **还有一堵速率墙（钱买不动的那种）**：余额 **< 10 MON 的 EOA 被 reserve-balance 规则限到 1 tx/3 块 ≈ 0.83 tx/s**。这就是为什么实测峰值 16 tx/s @17 条 0.14 MON 车道（理论 0.83×17≈14.2 吻合），也是为什么「80 tx/s」只是 40 道×2tps 的**配置目标**——想兑现它，每道要先躺上 ≥10 MON

所以预算 = 你想打多少笔 × 0.0066：

| 场景 | 笔数 | MON |
|---|---|---|
| 90 秒 demo @ 10 tx/s | 900 | **5.9** |
| 90 秒 demo @ 20 tx/s | 1,800 | **11.9** |
| 5 分钟 @ 10 tx/s | 3,000 | **19.8** |
| 10 分钟 @ 20 tx/s | 12,000 | **79** |
| 全程 6.5h @ 5 tx/s | 117,000 | **772** |
| **静默墙爆发（240 笔在 0.42s 内提交，随后几块落链）** | 240 | **1.6** |
| 人肉车道全场按住 60s（78 人的理论上限，实际远到不了） | ~4,680 | **~31** |

**所以 5 MON（公共水龙头一次的量）只够 90 秒 × 8 tx/s。** 这是必须提前解决的事，不要到现场才发现。

### 1.1b 测试币从哪来（按优先级）

| 来源 | 数量 | 说明 |
|---|---|---|
| **活动官方水龙头** | 最多 | `mojo.devnads.com/events/18` 的「水龙头」tab，**活动开始后开放**，参赛者额度远高于公共水龙头。这是首选 |

| 找主办方要 | 不确定 | 现场直接问 Monad DevRel。按档位说清楚需求：观众参与 + 静默墙只要 ~3 MON；要让 40 车道真跑接近 80 tx/s 的目标速率，需要每道 ≥10 MON 的**储备**（约 400 MON 躺账）外加 ~50 MON 的 gas 费——差一个数量级，别说错 |
| 多地址分批领 | 有风险 | 每个地址领一次再汇总。**只在前面都失败时用**，注意别把水龙头刷爆 |

### 1.1c 降本开关（钱不够时的调法）

```bash
# .env
GAS_LIMIT=60000        # 不能再低：50000 会 0/3 revert
GAS_PRICE_GWEI=105     # 贴着 baseFee 走，别给 150
BOTS=10                # 车道数：钱少就减车，不要减 gas
GAP_MS=1500            # 每条车道间隔，10 车道 × 1/1.5s ≈ 6.7 tx/s
```

> **别把 GAP_MS 往下调来求快**：余额 <10 MON 的车道被 reserve-balance 限在 0.83 tx/s（约 1.2s 一笔），比 1500ms 还紧。间隔不是瓶颈，储备才是——想超 0.83 tx/道，唯一办法是给每条道注 ≥10 MON。

### 1.1d 先算预算，再决定怎么演（做这一步，别跳）

```bash
node scripts/budget.mjs
```

它会读中继钱包的真实余额，按 **0.0066 MON/笔**（实测 60000 gas × 110 gwei）算出：
还能打多少笔、按计划演需要多少、缺口多少、现有钱能做到哪一档。

**三个数字必须先记住：**

| 项目 | 笔数 | 成本（gas 费） |
|---|---|---|
| 78 人各点一次 | 78 | 0.51 MON |
| 蜂群按 80 tx/s 目标打 90 秒 | 7,200 | 47.5 MON |
| 蜂群按 80 tx/s 目标打 10 秒 | 800 | 5.3 MON |

**「80 tx/s 连续 90 秒」这个画面有两道墙**：① 费率墙——7,200 笔的 gas 费 ≈ **48 MON**；② 储备墙——80 tx/s = 40 道 × 2 tps，每道余额 <10 MON 就被限到 0.83 tx/s，所以还要 **40 × 10 = 400 MON 躺在车道上**（不是花掉，是躺着）。两道都过才谈得上接近配置目标；实测口径永远以顶栏为准（17 条 0.14 MON 车道的历史峰值就是 16 tx/s）。

钱的多少直接决定台上能讲哪种话术：

| 预算 | 能做什么 | 台上怎么说（必须如实，且照顶栏念数） |
|---|---|---|
| ≥ 400 MON 储备 + ~50 MON 费 | 40 道满储备，可接近 80 tx/s 配置目标 | 「配置目标是每秒 80 笔；顶栏现在显示的是实测 X 笔」（X 照屏幕念） |
| 5–50 MON（每道 0.1–1.25 MON） | 蜂群跑真实负载，但每道被 reserve 限在 0.83 tx/s：17 道 ≈14、40 道 ≈33 tx/s 封顶，与 GAP_MS 无关 | 「峰值 16 tx/s 是我们量出来的；这条链对小余额账户有 1 tx/3 块的 reserve 限流，我们的曲线正好压在它给的物理线上——把每道注到 10 MON 就能解除，这可以现场验」 |
| < 5 MON | 只用合成打底，**把真实 gas 全留给观众点击** | 「这些格子是模拟密度；但你真的点一下，那笔是真的上链的」 |

**绝对不能做的事**：钱只够合成，却讲「全都是链上交易」。DevRel 会开浏览器查 tx，
现场被戳穿的代价远大于省下的钱。

顶栏会如实显示自己处在哪个模式：`实时 · <rpc>` = 全真实；`DEMO+链上` = 合成打底 + 真实点击；
`DEMO · 合成打底（链上读不到）` = 纯合成。**照顶栏说，不要照记忆说。**

### 1.3 中继 key 与蜂群车道注资（按物理墙算，别按感觉）

```bash
node server/index.mjs           # 首次会生成 .relayers.json 并打印 8 个地址
# Ctrl-C 停掉，给打印出的 8 个地址各打 ≥0.27 MON，再重启
```

> **为什么是 0.27**：中继 8 key 要同时撑「78 观众各一笔」+「静默墙 240 笔」= 318 笔 ≈ 2.1 MON，摊到 8 个 key ≈ 0.27 MON/key。老配置 0.05/key 只有 60 笔的额度，第 61 个人开始吃 502——当场穿帮就是这么来的。burst 前 `budget.mjs` 必须打印"够/不够 X 笔"，不够就只报付得起的 count。
> **蜂群车道是另一笔账**：注资 <10 MON/道 只是"能打"，速率被 reserve-balance 锁死在 0.83 tx/s/道。要么每道 ≥10 MON 解除限速，要么接受 0.83 tps/道的算术、台上用 §1.1d 第二行的诚实台词——没有第三种选择。

> 中继启动时会自检余额，没 gas 的 key 会「暂时停用」，补币后 30s 内自动恢复——不用重启。

### 评委问答

**Q：这不就是个像素画板吗？**
A：画板是表象。关键是每笔 claim 的写集零重叠、各占一个 slot——区块 #81474005 一个 ~1 秒块里 17 笔 claim 来自 17 个不同 EOA 全部落块（`docs/EVIDENCE.md` 一条 curl 可复现）。说准确点：若加一个全局计数器，官方语义下不会"退化成串行队列"，而是写集重叠触发乐观并行执行的**冲突重执行**，显著拖慢吞吐；我们零重叠，所以零重执行税。同负载放以太坊主网不是慢，是**买不起这种体验**：80 tx/s 是 ~15 tx/s 持续容量的 5 倍多，且 gas 单价×确认等待让"点了就亮"不可能；按我们实测峰值 16 tx/s（0.96 Mgas/s）算，纯 gas 容量主网其实塞得下——墙是价格和延迟，不是区块装不进。38 行合约是刻意的：把证明面积缩到一行 claim，性能故事全部交给状态划分本身。

**Q：80 tps 是假的/合成的吧？**
A：80 tx/s 是**配置目标**（40 道 × 2 tps 的算术），我们从不以实测口径讲它。实测是：17 条 0.14 MON 车道、峰值 16 tx/s——正好压在 Monad reserve-balance 物理线（<10 MON 限 1 tx/3 块）给的 0.83×17≈14.2 预测上。蜂群窗口 359 笔被节点接受、253 笔后撞限速墙、fail=6421（被链拒）；真落块全场 373 笔 = 蜂群 362 + 冒烟 1 + 观众 sync 10。墙长什么样是我们量出来的，这就是这份报告的价值；满屏 80+ 的画面出自合成密度层（顶栏如实标 DEMO）。

**Q：为什么用 40 个钱包而不是一个 relayer？**
A：一个 EOA 的 tx 按 nonce 严格串行。一个 relayer 就是一条车道，并行度上限等于独立发送方数量。这是 EVM 的硬约束，不是我们的实现选择。

**Q：观众点击是怎么上链的？**
A：服务端代付。8 个中继 key 轮转，每个 key 独立 nonce 队列，不 await receipt。观众不需要钱包、不需要 gas、不需要装任何东西。

**Q：和往届 #363 千人像素战争到底啥区别？（30 秒版）**
A：三点，当场可验：① **被拒的点击付不付钱。** #363 把冷却写进合约——同格被冷却拒掉的那几次点击，仍是一笔笔真交易、照样按 gasLimit 扣钱（Monad 上 revert 也烧钱，我们发了一笔注定失败的 `claim(9999)` 实测：`status=reverted`、`gasUsed=gasLimit=60000`、发送方余额实扣 0.0066 MON，物证在 `docs/EVIDENCE.md §5`）。我们的架构没有这笔税：合约 `claim()` 对合法 id 永成功，观众点击不存在「被拒还烧钱」；要做同格节流，冷却发生在中继代持层、发交易之前（`COOLDOWN_MODE=1` 演示开关，被拒点击 0 gas）。一页对照表：`docs/ab-result.json`（`node scripts/ab-demo.mjs`）。② **它比的是美学，我们比的是示波器。** 像素战争产出的是「一幅画」，好看但不可证伪；我们产出的是「每个格一个不相交写集」的性能仪器——并行的物证是区块 #81474005 里 17 个独立 EOA 同块全落（`docs/EVIDENCE.md`），一条 curl 可复现。③ **平台物理证据链。** 我们把 reserve-balance 限速线（<10 MON → 1 tx/3 块 ≈ 0.83 tx/s）、60k gas 硬下限、公共 RPC 100 块日志窗这些「只有真跑过才写得出」的约束量化进报告；#363 交付一个结果，我们交付一份 workload characterization。

### 4.2 收尾动作：结算（把「参与」变成真钱）

演示讲完、观众停手之后，**用一条命令给贡献榜发钱** —— 这是整个闭环的最后一环，
也是唯一能证明「参与不是计数器，是经济行为」的动作：

```bash
npm run settle -- --window 8000                          # 干跑：只算账，不发交易，随时可跑
npm run settle -- --from 81472000 --to-block 81479200 --top 3             # 干跑，覆盖本次演示爆发段
npm run settle -- --from 81472000 --to-block 81479200 --pot 0.02 --top 3  # 真转 0.02 MON 给前 3 名
```

- **为什么真结算用固定区间而不是 `--window`：** 窗口是「从当前块往回数」，链头一直在动，
  同一个 `--window 60000` 过十分钟就会截掉爆发段开头、得到不同的数字。固定区间 `--from/--to-block`
  重跑永远得到同一份排名（本例 362 条 claim / 21 个地址 / 紫 109）。

- **它证明什么：** 统计数据不是写死的数字，而是从 `Claim` 事件现场聚合出来的（每次跑都重新扫链）；
  转账是真交易，有 hash、有区块、有余额实差 —— 评委可以当场用 `eth_getTransactionReceipt` 复核。
- **讲的时候说什么：** 「刚才你们点的每一格，现在都变成了钱。前 3 名贡献者每人收到 0.0066 MON，
  三笔 tx 都在浏览器上。」（实测记录见 `docs/EVIDENCE.md §6`，含 3 个 tx hash 与余额对账）
- **三条硬约束，别踩：**
  1. 先干跑确认窗口内有人（`Claim 总数 > 0`）。演示结束后链上会安静，`--window 8000` 可能只有几条；
     要覆盖爆发段就用显式区间：`--from 81472000 --to-block 81479200`。
  2. 余额必须 ≥ `奖池 + gas`（每笔 `60000 × 110 gwei ≈ 0.0066 MON`）。脚本会自己检查并拒绝执行。
  3. 干跑永远不发交易；**带 `--pot` 才发钱**，别在演示中途手滑。

## 5. 故障降级矩阵（每种 30 秒内处置）

| 故障 | 现象 | 30 秒处置 |
|---|---|---|
| **RPC 挂** | 大屏左上角变红「连接中断」 | 改 `.env` 的 `RPC_URL` 换备用节点，重启 swarm；大屏会自动重连 |
| **网络全断** | 所有请求超时 | 大屏地址加 `?demo=1` → 合成流打底继续跑。**注意**：`?demo=1` 现在也会尽力连链（顶栏显示 `DEMO+链上`），所以网络恢复后观众的点击会自动重新出现在大屏上；顶栏若停在 `DEMO · 合成打底（链上读不到）` 就说明确实断网 |
| **音响不响** | 点了「开启声音」没声 | 检查系统输出设备；实在不行放弃声化，格子脉冲本身够看 |
| **蜂群崩** | 终端退出 / tps=0 | 重跑 `npm run swarm`（会自动重新同步 nonce）；降到 `BOTS=20` 更稳 |
| **中继崩** | 观众页「与中继失联」 | 重启 `node server/index.mjs`；观众页会自动重连，不用刷新 |
| **中继 key 没 gas** | 日志「没有 gas —— 暂时停用」 | 给那个地址打币，30s 内自动恢复，不用重启 |
| **爆发被冷却拒绝** | 导演台按完爆发，状态栏红字「发送失败 · 中继未连接」或回执 burst_cooldown | 中继有 15s 冷却（防连点烧 gas），等 ~16 秒再按。想连发就把 count 调小分两次 |
| **静默墙没打出真交易** | 大屏有涟漪+齐鸣，浏览器 tx 流里看不到这批 | 中继钱包没 gas。话术切到 budget.mjs 那档（合成打底），顶栏模式照念 |
| **静默墙/hold 发不出去** | `npm run swarm` 或观众页请求大量失败 | 先跑 `node scripts/budget.mjs` 看余额档位；不够就 `BOTS=10 GAP_MS=1500` 降载。注意就算钱够，<10 MON 的车道也发不过 0.83 tx/s——那是限速不是故障 |
| **页面白屏** | 大屏全黑 | F5；仍白则开 `?demo=1`；再不行播视频 |
| **二维码扫不开** | 手机打不开 | 先看大屏右下：出红色告警卡 = 中继没起，重跑 `node scripts/stage.mjs --check`；有码但扫不开 = 把二维码下方那行明文地址念给观众手输。**不要**改成局域网 IP —— 手机用流量时私网地址一样打不开 |
| **隧道起不来** | `stage.mjs` 60s 没拿到 trycloudflare 地址 | 换 `node scripts/stage.mjs --lan`，并让全场连同一个 wifi（4G 路由的 wifi 也行）；此时第 10 步改成「手机连该 wifi」 |
| **字幕推不到大屏** | 导演台点了字幕，大屏没反应 | 看导演台状态栏后缀：`· 跨设备` 说明中继通了，问题在大屏没轮询（F5 大屏）；`· 仅同屏` 说明导演台 POST 不到中继 —— 两页 origin 不同，用 `stage.mjs` 打印的同一组地址重开 |
